# GranBoard App

Appli Flutter (Android, **paysage**) de fléchettes, connectée en Bluetooth LE à une cible électronique GranBoard (Dash et 3s). Comptes joueurs et stats sur le serveur maison de foclabroc. Projet perso de foclabroc.

## Structure

- `lib/granboard.dart` : décodeur des trames BLE (`GranBoardDecoder.decode`) → `HitEvent` / `MissEvent` (bordure 3s) / `ButtonEvent` / `UnknownEvent`. `BoardTable` : tables calibrées.
- `lib/main.dart` : démarrage (paysage forcé + plein écran). `detectTv()` : canal `granboard/device` → `isTv` (Kotlin `MainActivity.kt`, `FEATURE_LEANBACK`) ou pref `tv_mode` ; TV → `TvHome`, sinon `HomePage` (cible, comptes, `TvLink.load`, `PlayerStore.sync()`). `GranBoardAppState.setTvMode` bascule téléphone ↔ écran.
- `lib/tv_link.dart` (téléphone) : `TvLink` — **plusieurs écrans** (`screens` : `TvScreen` code/hostKey/nom « TV »/« Tablette »), `link(code)` (`gb_tv_link`), `unlink`, `pushLobby()` (accueil), `pushGame(game, screen: game|results)` = `{screen, host, game: X01Game.toJson(), colors: {id: ARGB}, sound: bool}` via `gb_tv_push`, envoi « le dernier gagne » par écran. `soundOn` = `phone` ou code de l'écran qui joue le son (une TV reliée le prend si le son était sur le téléphone) ; son ailleurs → `AudioService.muted = true`. `tv_host`/`tv_code` → écran retiré. Prefs `tv_link_v2` (migration de `tv_link_v1`).
- `lib/tv/tv_client.dart` (TV) : `TvClient(deviceName, prefKey)` — salon `gb_tv_open(p_name)` (code + clé gardés en prefs `tv_room_v1`, même code après redémarrage), WebSocket Phoenix du relais (`wss://…/realtime/v1/websocket`, canal `realtime:<topic>`, heartbeat 25 s, reconnexion 5 s) : sur `broadcast` → `fetch()` (`gb_tv_get` depuis `seq`). Relecture de secours toutes les 1,5 s sans relais, 12 s avec. `debugSetState` pour les tests.
- `lib/tv/tv_home.dart` (TV) : écran code (4 cases, « Nouveau code », « Mode téléphone »), attente (« relié à … »), partie (`_TvGame` : rejoue le journal d'actions ; nouvelles actions appliquées une à une, effets seulement pour la dernière ; journal raccourci = annulation → reconstruit sans effet), résultats (`ResultsPage(tv: true)`, sans boutons). Son seulement si `state.sound` est vrai ; musique hors partie. Couleurs des joueurs via `PlayerStore.remoteColors`.
- `lib/board_service.dart` : connexion BLE partagée (singleton), flux `events` (jeux) et `frames` (diagnostic, calibration), dernière cible mémorisée, table calibrée par cible, `injectFrame` pour les tests.
- `lib/game/darts_game.dart` : interface commune `DartsGame` (kind, title, rulesLabel, players, current, round, finished, turnOver, winners, turnHits, throwDart/next/undo, actionLog, toJson, applyLogEntry) + `gameFromJson` (TV : `kind` = x01 | cricket | match) + `parseLogEntry`/`logEntryOf`. Un nouveau jeu = un moteur qui l'implémente + une vue + un cas dans `gameView`/`resultsPageFor` (`game_page.dart`), `GameFx.afterAnyDart/afterAnyNext`, `PlayerStore.record…`.
- `lib/game/cricket.dart` : `CricketGame` (variantes `CricketVariant`, `teams` = marques/points communs à l'équipe, `roundLimit` 20 par défaut, `seed` pour Caché/Wildcard → mêmes cibles téléphone et TV). Fin : tout fermé avec score ≥ (Cut Throat ≤) aux autres, sinon limite de manches (départage aux marques). Cut Throat : points aux adversaires qui n'ont pas fermé, SPOILER = un adversaire a tout fermé avec moins de points (3 joueurs et plus). Caché : 7 cibles au hasard parmi 1-20 + bull, la fléchette qui découvre compte. Wildcard : 6 numéros 7-20 + bull, ceux que personne n'a marqués sont retirés à chaque manche. Triple Only : 20-15 sans bull, seuls les triples. Mickey Mouse : 20-12 + D (`kDoublesTarget`) + T (`kTriplesTarget`) + bull ; un double/triple inutile marque sur D/T. Stats : MPR, meilleure manche (marques), 5+ marques.
- `lib/game/practice.dart` : `PracticeGame` (moteur commun : manches, tours de 3 fléchettes extensibles `maxDarts`, joueurs `done`/`out`, rejeu, action `c:<n>` = changer de cible) + `PracticeRules` par jeu (`PracticeKind`, réglages `kPracticeInfo` : manches, objectifs, cible, options). Règles choisies (validées par foclabroc) dans `docs/regles_granboard.md` ; Spider et Pirates « proches » (règles officielles non publiées). Jeux de **fête** dans le même moteur (`PracticeInfo.party`, min/max joueurs) : état commun `game.shared`, hooks `over` (dernier survivant…), `skipTurn` (tour passé), `grid` (`PracticeGrid`/`PracticeCell` affichée à la place de la cible).
- `lib/game/match.dart` : `MatchGame` (legs 3-13, `pattern` 01/Cricket par leg, premier à la majorité, le joueur qui commence tourne) ; « n » après la fin d'un leg = leg suivant (`betweenLegs`, bouton « LEG SUIVANT »).
- `lib/game/x01.dart` : moteur X01/Freeze **pur Dart**. État recalculé en rejouant les actions : `undo()` retire la dernière. Journal sérialisable (`actionLog` : `n` suivant, `m` ratée, `d:<numéro>:<anneau>`), `toJson` / `X01Game.fromJson` / `applyLogEntry` (TV, jeu à distance). Fins : `checkoutRoutes` (meilleure d'abord : tableau classique `_doubleOutChart` en Double Out, sinon recherche notée ; jusqu'à 3, mise en cache), `game.checkoutOptions`, `suggestCheckout` = la première.
- `lib/server.dart` : `GbServer` (RPC PostgREST `gb_*`, même URL et clé que Pixel Trade), `ApiError` (messages en français). Les erreurs renvoyées `{"error": …}` sont converties en `ApiError` (aussi via `debugRpc` des tests).
- `lib/players.dart` : `PlayerStore` = comptes mémorisés sur le téléphone (prefs `accounts_v1` : id, pseudo, couleur, **jeton de session**, dernier profil serveur en cache) + parties en attente (prefs `pending_games_v1`, joueurs désignés par `pid`, jeton ajouté à l'envoi). `recordX01` (invités exclus) → `flush()` ; hors ligne : gardé et renvoyé au prochain `sync()`/`flush()`. Session refusée → compte `expired` (« À RECONNECTER »), la partie attend la reconnexion. `ratingClass(note)`. `X01Player.id` = id serveur en texte, ou `guest-N` pour un invité (`isGuestId`).
- `lib/audio.dart` : `AudioService` (effets, musique de menu, annonceur `say`/`sayLater`). Toute erreur audio est avalée.
- `lib/ui/theme.dart` : palette `Tv`, `Tv.theme()`, `TvSection`, `TvBackground`.
- `lib/ui/dartboard.dart` : `BoardSkin` (classic | pub en bois, `BoardSkin.current`, pref `board_skin`, envoyé à la TV dans `skin`), `DartboardPreview`, `Dartboard` (cible dessinée, surbrillance + badges) et **`AnimatedDartboard`** (partie : fléchettes plantées vues de face aux couleurs du joueur, `dartPoint` = point d'impact stable par zone, onde à l'impact, zones qui pulsent en continu, éclair rouge bust / or victoire).
- `lib/ui/game_fx.dart` : `GameFx` (sons, annonceur, vibrations, annonces animées après une fléchette / « suivant » / victoire) + `GameSplash` ; partagés téléphone / TV.
- `lib/ui/` : `home_page` (grille de jeux : barre du haut logo + `_BoardPill` état cible + TV + Classements + Sons + ⋮ (style de la cible, mises à jour) + `_MeChip` → Joueurs ; tuiles 01 (grande), Cricket, Match, Entraînement, Fête → `SetupPage(kind:)` ; icône TV verte si reliée → `tv_sheet` : écrans reliés, ajout, `SoundTargetPicker` « Le son sort sur », aussi dans `sound_settings`), `account_page` (connexion / création, PIN sur pavé numérique à l'écran, création = code tapé 2 fois), `players_page` (+ `PlayerDetailPage`, `RatingBadge`), `ranking_page` (onglets note, victoires, moyenne, 180, meilleure fin, meilleure manche), `setup_page` (2 colonnes ; jeu 01 / CRICKET / MATCH / ENTRAÎN. / FÊTE (nombre de joueurs vérifié) ; comptes + invités + « Ajouter un joueur »), `game_page` (`GameLayout` partagé avec la TV : cible animée (zone à viser en contour blanc, `targets`) | joueur en cours (`_CheckoutRow` : « FIN » + cases vertes + « ou … ») + boutons | tableau des scores ; envoie l'état à la TV après chaque action), `results_page` (podium | stats ; envoi au serveur en arrière-plan + message), `cricket_view` (`CricketLayout` façon GranBoard, sans cible : `_History` manches du joueur | `_MarksArena` numéros au centre, colonnes des côtés réparties à gauche/droite, numéro mort barré | `_RightPanel` MPR + 3 fléchettes + boutons compacts (`_ActionBar(compact)`) ; `_PlayersBar` en bas (score, avatars, bandeau couleur du joueur en cours) ; grandes marques animées après la 3e fléchette ; couleurs distinctes par joueur (`PlayerStore.distinctColors` : couleur du compte sinon couleur libre, aussi dans `practice_view`) ; ## Serveur (comptes et stats)

- Serveur maison de Pixel Trade : PostgreSQL 17 + PostgREST derrière Caddy, `https://api.foclabroc.duckdns.org`, même clé publique `sb_publishable_…`. Tables et fonctions **préfixées `gb_`**, à côté de celles de Pixel Trade (`rc_`), sans y toucher.
- Fichier initial : `sql/2026-11-11_comptes_stats.sql` (tables `gb_players`, `gb_sessions`, `gb_games`, `gb_game_players`). Objets à `rc_owner`, aucun droit de table pour `anon`, fonctions internes `gb__*` fermées à l'API, RPC `gb_*` ouvertes à `anon`. Finir par `notify pgrst, 'reload schema';`.
- RPC : `gb_register(pseudo, pin, color)`, `gb_login(pseudo, pin)` (**renvoie** `{error: unknown|pin(+left)|locked(+minutes)}` au lieu de lever : une exception annulerait le compteur d'essais ; 5 erreurs → bloqué 15 min), `gb_check(tokens[])`, `gb_logout`, `gb_set_color`, `gb_set_pin`, `gb_submit(game)` (anti-doublon par `cid`, garde-fous sur les valeurs, invités jamais envoyés), `gb_profile(id)` (stats, note, rang, 20 dernières parties), `gb_top(kind)` (rating, wins, avg, n180, checkout, high ; note et moyenne à partir de 3 parties).
- Salon TV (`sql/2026-11-11_salon_tv.sql`, table `gb_tv`) : `gb_tv_open(p_name)` → {code 4 car., key, topic} (colonne `tv_name`), `gb_tv_link(code, nom)` → {code, host_key, name} (le dernier relié pilote, état remis à « lobby »), `gb_tv_push(code, host_key, state)` (128 Ko max, `tv_host` sinon) → seq + notification, `gb_tv_get(code, key, since)` → {seq[, state]} ou {error: tv_gone}. Notification via `rc__rt_safe(gb__tv_topic(code), 'gb', {seq})` (`'rc_' || 24 hex` de sha256('gbtv|'+code), format accepté par le relais `rc-realtime`). Salons inactifs 2 jours supprimés à l'ouverture d'un nouveau. Le relais traite ce canal comme « joueur » (rc__rt_here/gone) : sans effet, aucun joueur ne correspond.
- Cricket (`sql/2026-11-11_cricket.sql`) : `gb_games.kind` (x01 | cricket) + `variant`, `gb_game_players.marks`. `gb_submit` accepte `kind` (garde-fous Cricket : marques ≤ 3 × fléchettes, manche ≤ 9). `gb__stats` : stats 01 filtrées sur `kind = 'x01'` + `cr_games`, `cr_wins`, `cr_marks`, `cr_best`, `mpr` (`gb__mpr` : 20 dernières parties, 3 minimum). `gb_top` : + `mpr`, `cr_wins`. `gb_profile.recent` : + `kind`, `mpr`. Un leg de Match est envoyé comme une partie de son jeu.
- Entraînement (`sql/2026-11-11_entrainement.sql`) : `kind = 'practice'`, `variant` = nom du `PracticeKind`, `points` = score (négatif permis), `marks` = fléchettes utiles. `gb__practice` (meilleur score par jeu) → `stats.practice` via `gb__stats_all` dans `gb_profile` ; `gb_top('pr:<jeu>')` = meilleur score de chaque joueur (`gb__top_practice`) ; `recent` + `points`.
- Note = moyenne aux 3 fléchettes des 20 dernières parties **de 01** (`gb__rating`). Classe côté appli (`ratingClass`) : D < 25, C, B ≥ 35, A ≥ 45, AA ≥ 55, AAA ≥ 65, MASTER ≥ 80.
- Jetons de session : 24 octets aléatoires, seule l'empreinte sha256 est stockée (`gb_sessions`). PIN chiffré en bcrypt (`extensions.crypt`).
- Tester le SQL avant de le donner : PostgreSQL local dans le sandbox (`apt-get install postgresql`, rôles `anon`/`authenticated`/`rc_owner`, schéma `extensions` + pgcrypto), lancer le fichier deux fois, puis les RPC en `set role anon`.
- Les profils locaux des versions ≤ 0.3.3 (prefs `players_v1`) ne sont plus utilisés.

## Règles implémentées (X01)

- Bust (retour au score de début de manche) si : dépassement, reste 1 en Double/Master Out, fin sur une mauvaise fléchette, fin alors que l'équipe est gelée.
- Master = double, triple ou bull. Bull 50/50 : le 25 vaut 50 et compte comme un double.
- « Suivant » avant 3 fléchettes : fléchettes manquantes = ratées (moyenne). Fléchettes reçues après la fin de manche ignorées. Bordure 3s (`OUT@`) = ratée.
- Limite de manches : le plus petit reste gagne (total d'équipe en Freeze).
- Freeze 01 : 2 équipes de même taille, alternance A1, B1, A2, B2 ; équipe gelée si son total restant est strictement supérieur à celui de l'adversaire ; le joueur qui finit fait gagner son équipe.
- Stats envoyées seulement en ouvrant les résultats (pas si la partie est abandonnée).

## Protocole GranBoard

- L'appli écoute toutes les characteristics `notify`/`indicate`.
- Fléchette = texte ASCII `ligne.colonne@` (ex. `3.4@` = T20) ; bouton = `BTN@` ; bordure extérieure de la 3s = `OUT@`. `frameKey` ne garde que l'ASCII visible (la 3s ajoute probablement des octets invisibles).
- Table `GranBoardDecoder._codes` commune à la **Dash** et à la **3s** (vérifié par calibration le 11/11/2026). Bull 25 = `8.0@`, Bull 50 = `4.0@`.
- Calibration (autres modèles) : 82 zones à partir du 20 + étape bordure, table par cible (prefs `board_table_<remoteId>`), « Copier la table » pour l'intégrer ensuite. La cible n'accepte qu'une connexion BLE.
