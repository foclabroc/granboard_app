# Foclaboard (dépôt granboard_app)

Appli Flutter (Android, **paysage**) de fléchettes, connectée en Bluetooth LE à une cible électronique GranBoard (Dash et 3s). Comptes joueurs et stats sur le serveur maison de foclabroc. Projet perso de foclabroc.

## Structure

- `lib/granboard.dart` : décodeur des trames BLE (`GranBoardDecoder.decode`) → `HitEvent` / `MissEvent` (bordure 3s) / `ButtonEvent` / `UnknownEvent`. `BoardTable` : tables calibrées.
- `lib/main.dart` : démarrage (paysage forcé + plein écran). `detectTv()` : canal `granboard/device` → `isTv` (Kotlin `MainActivity.kt`, `FEATURE_LEANBACK`) ou pref `tv_mode` ; TV → `TvHome`, sinon `HomePage` (cible, comptes, `TvLink.load`, `PlayerStore.sync()`). `GranBoardAppState.setTvMode` bascule téléphone ↔ écran.
- `lib/tv_link.dart` (téléphone) : `TvLink` — **plusieurs écrans** (`screens` : `TvScreen` code/hostKey/nom « TV »/« Tablette »), `link(code)` (`gb_tv_link`), `unlink`, `pushLobby()` (accueil), `pushGame(game, screen: game|results)` = `{screen, host, game: X01Game.toJson(), colors: {id: ARGB}, sound: bool}` via `gb_tv_push`, envoi « le dernier gagne » par écran. `soundOn` = ensemble d'appareils qui jouent le son (`phone` et/ou codes d'écran, jamais vide ; `toggleSound`, `setSoundOn` = un seul ; prefs : liste, ancien texte accepté ; une TV reliée le prend si seul le téléphone l'avait) ; téléphone absent de l'ensemble → `AudioService.muted = true`. `tv_host`/`tv_code` → écran retiré. Prefs `tv_link_v2` (migration de `tv_link_v1`).
- `lib/tv/tv_client.dart` (TV) : `TvClient(deviceName, prefKey)` — salon `gb_tv_open(p_name)` (code + clé gardés en prefs `tv_room_v1`, même code après redémarrage), WebSocket Phoenix du relais (`wss://…/realtime/v1/websocket`, canal `realtime:<topic>`, heartbeat 25 s, reconnexion 5 s) : sur `broadcast` → `fetch()` (`gb_tv_get` depuis `seq`). Relecture de secours toutes les 1,5 s sans relais, 12 s avec. `debugSetState` pour les tests.
- `lib/tv/tv_home.dart` (TV) : écran code (4 cases, « Nouveau code », « Mode téléphone »), attente (« relié à … » ; `tv_idle.dart` : `FloatingBoard` cible qui flotte sans tourner, aussi sur l'écran code, `TvTopPanel` à gauche = `gb_top` rating/avg/mpr/n180/checkout, 6 lignes, change toutes les 9 s, relu toutes les 2 min, `TvRecentPanel` à droite = `gb_profile.recent` des comptes du téléphone (`ids` envoyés par `pushLobby`), regroupés par date = même partie, 4 dernières, relu toutes les 45 s ; faux serveur `recentOf`), partie (`_TvGame` : barre du haut + **`NextUpChip`** (`tv/next_up.dart` : « ENSUITE » = joueur suivant, `nextUp(game)` rejoue la partie dans une copie et fait `next()`, « IL LUI RESTE N » en 01, points en Cricket, score en entraînement ; rien en solo, à la fin ou entre 2 legs ; recalculé seulement quand le journal change ; `test/next_up_test.dart`) ; rejoue le journal d'actions ; nouvelles actions appliquées une à une, effets seulement pour la dernière, après l'image ; journal raccourci = annulation → reconstruit sans effet), résultats (`ResultsPage(tv: true)`, sans boutons). Son seulement si `state.sound` est vrai ; musique hors partie. Couleurs des joueurs via `PlayerStore.remoteColors`.
- `lib/game_save.dart` : **reprise d'une partie coupée** — `GameSave.save(game, tournament:)` (pref `saved_game_v1` = {game JSON avec journal, tn {uid, r, s}, at} ; effacée si aucune action), appelé par `GamePage._pushTv` hors ligne de jeu en ligne ; `_close()` (résultats, abandon, partie finie quittée) l'efface ; `load()` (null après 3 jours) → `SavedGame` (`summary`). `HomePage._offerResume` (au lancement, sauf premier accueil) : dialogue « Partie interrompue » REPRENDRE (`resume-yes`) / ABANDONNER (`resume-no`) ; tournoi à la maison → `LocalTournamentPage(uid, resume: (partie, r, s))` qui relance le match. `test/resume_test.dart`.
- `lib/lan.dart` : **écran par le Wi-Fi local, sans internet** — écran : `LanServer` (HTTP `kLanHttpPort` 47811, sinon port libre ; `POST /push` {code, state}, 403 si autre code ; UDP `kLanUdpPort` 47812 : « FOCLA?<code> » → « FOCLA!<code>|<port>|<nom> ») démarré par `TvClient.start` ; téléphone : `Lan.discover(code)` (diffusion 255.255.255.255 + x.x.x.255 de chaque réseau, 3 essais en 1,8 s), `Lan.push`. `TvLink.link` cherche en même temps sur le Wi-Fi (serveur injoignable + écran trouvé = `TvScreen` sans `hostKey`, `wifiOnly`) ; `TvScreen.lan` (ip:port, gardé) ; `_push` envoie par le serveur ET le Wi-Fi (`_flushLan`, `_rediscover` au plus toutes les 20 s, `lanWorks` → icône wifi dans `tv_sheet`) avec `at` (heure d'envoi) : `TvClient._applyState` garde le plus récent. Écran sans internet au démarrage : code fait lui-même (`lanOnly`, pref `<prefKey>_lan`, message « SANS INTERNET : LE TÉLÉPHONE DOIT ÊTRE SUR LE MÊME WI-FI »). `Lan.enabled = false` dans `flutter_test_config`, `test/lan_test.dart` (boucle locale). Jamais essayé sur de vrais appareils (diffusion UDP filtrée par certains Wi-Fi ?).
- **Double en ligne** (2 contre 2, une maison par équipe ; SQL `2026-11-13_double.sql` : `gb__on_players_ok` (ids uniques, comptes existants ou `guest-…`), `gb_on_invite` accepte une partie `double: true` à 3 joueurs (moi, mon équipier, l'adversaire), `gb_on_answer(…, p_game)` = partie complétée à 4 joueurs, seuls `players` et `home` peuvent changer). JSON de la partie : `double: true` + `home` {id: a|b} (a = qui défie). `askDouble` (1 CONTRE 1 / 2 CONTRE 2) et `pickTeammate` (compte du téléphone ou invité `guest-a1`/`guest-b1` « Invité de X ») dans `online_page` ; `SetupPage(online: [moi, adversaire, équipier])` = mode double (`_double` : 01 `X01Settings.doubles` ou Team Cricket seulement, panneau 2 contre 2) ; `completeDouble` (`online.dart`) ajoute l'équipier et remet les joueurs en alternance ; `OnlineRoom.mine(id)` (joueur de ma maison, via `home`, sinon `myId`) utilisé par `GamePage._canAct` et l'annulation. **01 en double** (`X01Settings.doubles`, json `dbl`, nom « Double 501 », `teamPlay` = freeze ou doubles) : `_shareScore` donne le même score et l'ouverture aux coéquipiers, le joueur qui finit fait gagner l'équipe, chacun garde sa moyenne. `test/doubles_test.dart`, `online_test` (double).
- **Hors ligne** : `GbServer.reachable` (ValueNotifier, faux après une erreur réseau) ; `PlayerStore.startAutoSync()` (lancé par `main.dart`) : toutes les 30 s `flush()` ou `gb_check([])`, `sync()` dès que le serveur revient ; `flush` prévient les écouteurs ; `_NetPill` dans la barre de l'accueil (nuage barré rouge hors ligne, nuage orange + nombre si parties en attente, toucher = explication + envoi) ; classements hors ligne = « HORS LIGNE » + explication.
- `lib/board_service.dart` : connexion BLE partagée (singleton), flux `events` (jeux) et `frames` (diagnostic, calibration), dernière cible mémorisée, table calibrée par cible, `injectFrame` pour les tests, caractéristique d'écriture (service `442f1570-8a00-9a28-cbe1-e1d4212d53eb`, sinon 1re d'un service non standard) → `BoardLights.writer`.
- `lib/board_lights.dart` : **lumières de la 3s** (protocole non officiel de keenanlk/granboard-ble-codes, jamais vu marcher depuis le sandbox : à confirmer par foclabroc) — commandes 16 octets (`command(type, a, b, pos, dur, keep)` : 0x01-0x03 clignotement d'une LED, 0x11 vague, 0x14 contour fixe, 0x17 contour clignotant ; `kLedPos` numéro → LED 0-59) et 20 octets (numéros, 0x05 = orange) ; file d'attente 70 ms, contour et numéros remplacés si encore en attente, renvoyés seulement s'ils changent ; `dart(game, hit, color)` (touche, bust rouge, 180 / victoire = vague) et `state` appelés par `GamePage` (`_dart`, `_pushTv`), `clear()` au `dispose` ; `targetsOf(game)` (Cricket : ouverts pour le joueur et pas morts ; 01 : 1re fléchette de la fin conseillée ; entraînement : `targetZones` ; bull jamais) ; prefs `board_lights_v1` / `board_numbers_v1` ; réglages `lights_sheet.dart` (⋮ › Lumières de la cible, ESSAYER). `test/lights_test.dart`.
- `lib/game/bot.dart` : **bot** (affiché « Joueur virtuel » : bouton « Joueur virtuel » de `setup_page`, nom « Joueur virtuel N », étiquette VIRTUEL ; `isBotId` = `guest-bot<n>`, donc invité : pas de stats ni de compte, avatar robot dans `PlayerAvatar`). `Bot.aim(game)` = zone visée (01 : fin conseillée, sinon T20, double d'ouverture, placement sur un double ; Cricket : fermer ses numéros dans l'ordre puis marquer ; entraînement / fête : zone de `targetZones` au plus gros multiplicateur, sinon T20), `throwAt(aim, sigma)` = point visé + bruit gaussien sur la géométrie de `dartboard.dart` (`zoneAt`), `sigmaFor(PPR | MPR)` étalonné au T20 (Monte-Carlo, graine fixe), `target(game, ratingOf)` = moyenne des humains : note sur 20 → PPR/MPR (`bandValue`, inverse de `bandRating` ; invité = note 3), mélangée à leur moyenne réelle de la partie (poids darts / (darts + 12)), rattrapage ×0,85 / ×1,12 au-delà de 80 points (01) ou 60 (Cricket). `GamePage` : `_botTurn` (jamais en ligne ; entre 2 legs seulement sans humain), `_scheduleBot` (1,5 s 1re fléchette, 1,1 s les suivantes, 1,8 s avant « suivant », attend la fin d'une vidéo), `_canAct` faux pour l'humain pendant le tour du bot (cible ignorée), annulation jusqu'à la dernière action d'un humain. `test/bot_test.dart` (tous les jeux finis par des bots).
- `lib/game/darts_game.dart` : interface commune `DartsGame` (kind, title, rulesLabel, players, current, round, finished, turnOver, winners, turnHits, throwDart/next/undo, actionLog, toJson, applyLogEntry) + `gameFromJson` (TV : `kind` = x01 | cricket | match) + `parseLogEntry`/`logEntryOf`. Un nouveau jeu = un moteur qui l'implémente + une vue + un cas dans `gameView`/`resultsPageFor` (`game_page.dart`), `GameFx.afterAnyDart/afterAnyNext`, `PlayerStore.record…`.
- `lib/game/cricket.dart` : `CricketGame` (variantes `CricketVariant`, `teams` = marques/points communs à l'équipe, `roundLimit` 20 par défaut, `seed` pour Caché/Wildcard → mêmes cibles téléphone et TV). Fin : tout fermé avec score ≥ (Cut Throat ≤) aux autres, sinon limite de manches (départage aux marques). Cut Throat : points aux adversaires qui n'ont pas fermé, SPOILER = un adversaire a tout fermé avec moins de points (3 joueurs et plus). Caché : 7 cibles au hasard parmi 1-20 + bull, la fléchette qui découvre compte. Wildcard : 6 numéros 7-20 + bull, ceux que personne n'a marqués sont retirés à chaque manche. Triple Only : 20-15 sans bull, seuls les triples. Mickey Mouse : 20-12 + D (`kDoublesTarget`) + T (`kTriplesTarget`) + bull ; un double/triple inutile marque sur D/T. Stats : MPR, meilleure manche (marques), 5+ marques.
- `lib/game/practice.dart` : `PracticeGame` (moteur commun : manches, tours de 3 fléchettes extensibles `maxDarts`, joueurs `done`/`out`, rejeu, action `c:<n>` = changer de cible) + `PracticeRules` par jeu (`PracticeKind`, réglages `kPracticeInfo` : manches, objectifs, cible, options). ## Serveur (comptes et stats)

- Serveur maison de Pixel Trade : PostgreSQL 17 + PostgREST derrière Caddy, `https://api.foclabroc.duckdns.org`, même clé publique `sb_publishable_…`. Tables et fonctions **préfixées `gb_`**, à côté de celles de Pixel Trade (`rc_`), sans y toucher.
- Fichier initial : `sql/2026-11-11_comptes_stats.sql` (tables `gb_players`, `gb_sessions`, `gb_games`, `gb_game_players`). Objets à `rc_owner`, aucun droit de table pour `anon`, fonctions internes `gb__*` fermées à l'API, RPC `gb_*` ouvertes à `anon`. Finir par `notify pgrst, 'reload schema';`.
- RPC : `gb_register(pseudo, pin, color)`, `gb_login(pseudo, pin)` (**renvoie** `{error: unknown|pin(+left)|locked(+minutes)}` au lieu de lever : une exception annulerait le compteur d'essais ; 5 erreurs → bloqué 15 min), `gb_check(tokens[])`, `gb_logout`, `gb_set_color`, `gb_set_pin`, `gb_submit(game)` (anti-doublon par `cid`, garde-fous sur les valeurs, invités jamais envoyés), `gb_profile(id)` (stats, note, rang, 20 dernières parties), `gb_top(kind)` (rating, wins, avg, n180, checkout, high ; note et moyenne à partir de 3 parties).

## Règles implémentées (X01)

- Bust (retour au score de début de manche) si : dépassement, reste 1 en Double/Master Out, fin sur une mauvaise fléchette, fin alors que l'équipe est gelée.
- Master = double, triple ou bull. Bull 50/50 : le 25 vaut 50 et compte comme un double.
- « Suivant » avant 3 fléchettes : fléchettes manquantes = ratées (moyenne). Fléchettes reçues après la fin de manche ignorées. Bordure 3s (`OUT@`) = ratée.
- Limite de manches : le plus petit reste gagne (total d'équipe en Freeze).
- Freeze 01 : 2 équipes de même taille, alternance A1, B1, A2, B2 ; équipe gelée si son total restant est strictement supérieur à celui de l'adversaire ; le joueur qui finit fait gagner son équipe.
- Stats envoyées seulement en ouvrant les résultats (pas si la partie est abandonnée).

## Protocole GranBoard

- L'appli écoute toutes les characteristics `notify`/`indicate`.
- Fléchette = texte ASCII `ligne.colonne@` (ex. `3.4@` = T20) ; bouton = `BTN@` ; bordure extérieure de la 3s = `OUT@`. `frameKey` ne garde que l'ASCII visible (la 3s ajoute probablement des octets invisibles).
- Table `GranBoardDecoder._codes` commune à la **Dash** et à la **3s** (vérifié par calibration le 11/11/2026). Bull 25 = `8.0@`, Bull 50 = `4.0@`.
- Calibration (autres modèles) : 82 zones à partir du 20 + étape bordure, table par cible (prefs `board_table_<remoteId>`), « Copier la table » pour l'intégrer ensuite. La cible n'accepte qu'une connexion BLE.
